# Cockpit 路线图

> 目标：把 dsh-cockpit 从「一个好看的看板」升级成 **DeepSeek Harness 的任务指挥层（Mission Control）**，并围绕它长出插件生态。
> 适用版本：v1.0.0

---

## 0. 一句话定位

**DSH 是干活的引擎，Cockpit 是坐在引擎上的指挥台。**

用户装上 DSH 之后，第一件事不是读文档，而是想「我这一堆会话、一堆 agent 到底在干嘛」。Cockpit 就回答这一个问题，并顺手让用户能在同一个界面里**做决定**（审批、发话、改任务）。

它不是：又一个 HUD、又一个会话列表、又一个成本面板。
它是：这些单点能力的**聚合层与操作层**。

---

## 1. 为什么它有资格做核心插件

**DSH 的结构性缺口**：原生界面是「一次一个会话」。当用户开始用 agent team（一个 lead + 若干 teammate 并行），全局感立刻消失：谁在干什么、卡在哪、要不要我确认、改的是不是同一个文件——用户只能一个个会话点开看。

**现有生态的空白**：awesome-dsh-plugin 里约 2800 条，绝大多数是单点工具（rewind、voice、cost、notification），**没有任何一个「指挥层」**；HUD 类只显示状态不承载操作。位子空着。

**我们已经有的差异资产**（别人复制要花同样代价）：

| 资产 | 说明 |
| --- | --- |
| 真实 teammate 遥测 | 追到每个 member 自己的 session 日志，token/动作/活动条是真的 |
| 任务板 + 写域冲突 | 共享任务、依赖、两人同改一个文件的红色告警 |
| 计划兜底 | 没有任务板时用本轮 todo 铺满看板，永远不空 |
| 审批闸口（v0.3） | deck 里直接允许一次 / 拒绝，25 秒不回退原生弹窗 |
| 工作台内嵌 | 侧栏入口，主区面板，同一套主题 |
| 视觉与性能 | 液面进度、编队泳道、深色跟随、SSE 合并去重 |

## 2. 核心产品形态（v1.0 四块）

### A. 指挥（看）
会话切换、编队成员与状态、任务板/计划、实时活动流、文件写域冲突、审批待办、每轮变更与耗时。加一个 **Ctrl+K 命令面板**（跳会话、搜任务、发起审批策略切换、给 agent 发消息）。

### B. 操作（做，最小集）
只碰四类写操作，全部**用户显式触发**、可审计：

1. 审批：允许一次 / 拒绝（已完成）
2. 对 agent：发一条消息、中断当前轮、继续
3. 对任务：改状态、重新指派、解除阻塞
4. 对视图：聚焦某个会话（点卡片跳到 DSH 对应会话）

> 明确不做：自动派生 agent、自动同意、批量改代码。指挥台不是自动驾驶。

### C. 产物（Artifacts）
每轮变更摘要（文件 + 增删行）、测试结果、关键命令输出；有检查点能力时提供「回滚到某轮」（依赖 DSH rewind，先做展示 + 跳转，再谈写）。

### D. 多端
工作台内嵌（默认）→ 独立页（第二块屏）→ 手机 PWA（局域网配对，可选 HTTPS 隧道）。同一个 state 契约，三种壳。

## 3. 生态：三圈扩展

### 圈 1 · 展示扩展（Cockpit Extension API）
宿主侧（host）暴露聚合后的只读 state；UI 侧提供注册点，第三方插件把自己的东西挂到 deck 上：

```js
// 概念 API
cockpit.registerCard({ slot: 'side' | 'board' | 'rail', id, title, render(state, ctx) })
cockpit.registerPanel({ id, title, icon, render })
cockpit.registerActivityKind({ kind, label, render })
cockpit.registerCommand({ id, title, run })
cockpit.contribute({ point: 'round.stats', rows: [{ label, value }] })
```

- **卡片要能带操作**：`actions` 声明式（标题 + handler），权限走宿主统一审计。
- **隔离**：扩展 UI 跑在 iframe 内（同源模块加载），拿不到宿主 DOM；host 侧插件只能通过 `cockpit.extend` 贡献数据，命名空间 `ext.<plugin>`。
- **SDK**：`@dsh-cockpit/sdk` 只含类型 + 小工具（不发 UI、不带依赖），保证第三方插件体积小。

**首批官方示例**（同时是生态模板）：
1. `cost` — 本轮/今日成本、余额、预算告警（注入「本轮」卡片一行）
2. `git` — 当前分支、未提交改动、与 teammate 写域的冲突叠加
3. `tests` — 最近测试结果与失败用例，点击跳日志
4. `calendar` — 定时任务/提醒，和 DSH schedule 打通
5. `device` — 手机配对与远程审批

### 圈 2 · 数据扩展
Cockpit 同时是一个 **只读 state provider**：其他插件可以 `cockpit:state` 订阅（暴露 `snapshot()` + `subscribe()`），不必自己重写一遍投影聚合。
反过来，其他插件可以向 deck `contribute` 字段（如 cost 往「本轮」加一行），实现「一个指挥台看全部」。

### 圈 3 · 分发与运营
- 发 npm（`dsh-cockpit`）+ GitHub Release + tgz，`dsh plugin add` 一键装
- 发布后按惯例提交到插件清单（资料已备）
- 模板：团队启动模板（lead + 前/后/测）、审批策略模板、deck 插件模板仓库
- 内容：3 秒 GIF（5 agent 并行 + 一键审批 + 写域冲突红色高亮）、B 站/YouTube 演示、X thread
- 主题/语言：内置深浅色 + 中英双语，第三方可加主题包

## 4. 技术支柱（让生态敢依赖）

1. **契约稳定**：`state` 加 schema 版本（`state.schema = 1`），字段只增不删；`docs/STATE.md` 就是契约，破坏性变更必须 bump major 并在 deck 里做双读。
2. **兼容层**：DSH 插件 API 仍在快速演进；用 `dsh-cockpit-compat` 把 projection key / agents 服务差异隔离，带版本探测，缺数据就少显示、不崩。
3. **安全模型**：local-only、同源写接口、审批只 allow-once、扩展声明式操作、写操作集中审计（一条 `~/.dsh/cockpit/audit.jsonl`）。
4. **性能预算**：state 帧 ≤ 30 KB、首屏 < 150 ms、常驻内存 < 60 MB、SSE 260 ms 合并去重；扩展渲染必须走 requestAnimationFrame 批处理。
5. **可测性**：fake-ctx harness（已有）+ preview server（已有）+ 截图回归；每个扩展点配契约测试。

## 6. 传播设计（为什么可能火）

- **视觉钩子**：3 秒能看懂——5 个 agent 同时干活、任务从待处理滑到已完成、红色写域冲突、一键放行审批。
- **场景钩子**：「一个人指挥一个开发团队」「下班路上用手机把审批点了」。
- **生态钩子**：第一条 deck 插件挑战；官方模板仓库；"把你的插件挂到指挥台" 一句话说清。
- **内容节奏**：README 双语 + 长截图 → B 站 2 分钟演示 → X thread → awesome list PR。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| DSH 插件 API 变动 | compat 层 + 版本探测 + 降级显示 |
| 审批被滥用/误点 | 只 allow-once、25s 回退、同源、审计日志、默认本地 |
| 性能随数据量退化 | 帧预算 + 合并 + 虚拟列表（活动流 > 200 条） |
| 与 HUD/其他插件定位重叠 | 明确「指挥层 vs 环境层」，HUD 做胶囊，Cockpit 做面板，v0.5 共享状态联动 |
| 生态冷启动 | 先自建 3 个官方示例 + SDK + 模板，降低第三方门槛 |
| 命名冲突 | 包名 `dsh-cockpit`，UI 品牌用 Cockpit（DSH 官方无同名） |
